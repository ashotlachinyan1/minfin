# ArmBudget — интерактивный портал государственного бюджета и госдолга РА

**Техническое задание для Claude Code · версия 1.0 · 29.09.2026**
Кодовое имя репозитория: `armbudget`. Рабочие языки интерфейса: հայերեն (по умолчанию), русский, English.

> Как пользоваться документом. Положите `PROJECT_SPEC.md`, `CLAUDE.md`, `PHASE_PROMPTS.md` и папку `seed/` в корень пустого репозитория. Запускайте Claude Code по фазам из `PHASE_PROMPTS.md`, одна фаза за сессию. Каждая фаза заканчивается проверяемыми критериями приёмки (раздел 14).

## 0. Стратегическая рамка (прочитать до кода)

### 0.1. Зачем этот продукт, если у Минфина уже есть «Interactive budget»
У Минфина РА есть страница [Interactive budget](https://www.minfin.am/en/page/interactive_budget) и отдельные разделы отчётности. Копировать её бессмысленно. Портал оправдан только в том случае, если он даёт то, чего у первоисточника нет:

| # | Отличие | Почему это ценно |
|---|---|---|
| 1 | **План и факт в одной модели**: проект → закон → уточнённый план → план периода → факт, на уровне программы и мероприятия | Недо- и перефинансирование видно сразу, без ручной сверки PDF-файлов |
| 2 | **Госдолг как портфель**: валюта, кредитор, инструмент, фикс/плавающая ставка, средняя ставка, график погашений, чувствительность к курсу | Минфин публикует остатки, но не аналитику риска |
| 3 | **Реальные величины**: дефлятор ВВП / ИПЦ из Armstat, % ВВП, на душу населения | Номинальный рост при инфляции вводит в заблуждение |
| 4 | **Сверка источников**: Минфин ↔ Armstat ↔ ЦБ ↔ МВФ, расхождения показываются, а не прячутся | Доверие к цифрам |
| 5 | **Каждая цифра со ссылкой**: документ, страница, таблица, дата публикации, уровень достоверности | Цифру можно проверить |
| 6 | **Открытые выгрузки**: CSV / XLSX / Parquet / статический JSON-API | Пригодно для журналистов, аналитиков, депутатов, банков |

### 0.2. Главный риск — данные, а не фронтенд
Фронтенд Claude Code соберёт за несколько сессий. 70–80% трудозатрат [оценка] уйдёт на:
1. **Извлечение** таблиц из PDF/XLSX/DOCX Минфина, формат которых меняется от года к году.
2. **Сквозную сопоставимость (crosswalk)** кодов программ и ведомств: ведомства реорганизовывались (крупная реструктуризация правительства в 2019 г.), программы переименовываются и сливаются.
3. **Единицы измерения**: приложения к закону о бюджете обычно даются в **тыс. драмов**, пресс-релизы — в млрд, долг — в млн USD. Каждый парсер обязан явно определять единицу.
4. **Доступность minfin.am**: при подготовке ТЗ сайт отказал в TLS-рукопожатии (`SSLV3_ALERT_HANDSHAKE_FAILURE`) и в чтении robots.txt. Краулеру нужен запасной SSL-контекст (раздел 5.4) и ручной fallback — загрузка файлов в `data/manual_drop/`.

**Решение по объёму MVP:** 2019–2026 (полноценный программный бюджет), а не 2008+. История 2006–2018 подключается позже из World Bank BOOST (раздел 4.3) как отдельный слой с пометкой «другая методология».

### 0.3. Pre-mortem: почему проект может провалиться через 6 месяцев
| Сценарий провала | Вероятность [оценка] | Превентивная мера |
|---|---|---|
| Парсеры сломались на новом формате отчёта, данные не обновляются | 60% | Контрактные тесты (pandera) + сравнение итогов с пресс-релизом, алерт в CI, ручной override-слой |
| Цифры портала расходятся с официальными, теряется доверие | 40% | Автоматическая сверка итогов (раздел 7), бейдж «сверено / расхождение X%» |
| Слишком сложно для обычного пользователя | 35% | Сначала главная страница «Бюджет за 60 секунд» и сценарии для каждой персоны (раздел 2) |
| Перекодировка программ между годами неверна, ряды ломаются | 50% | Таблица crosswalk с ручной валидацией и флагом `comparable=false` |
| Юридический или репутационный риск («неофициальные данные») | 15% | Явный дисклеймер, ссылки на первоисточник, отсутствие символики Правительства |

Какое свидетельство изменило бы рекомендацию: если Минфин публикует машиночитаемые (CSV/API) данные исполнения по мероприятиям — фазы 2–3 сокращаются вдвое, и фокус смещается на аналитику долга и сверку.

## 1. Цели и метрики успеха

- **G1.** Любой гражданин за ≤ 3 клика находит, сколько потрачено на выбранную сферу (например, «Образование → Общее образование»), сколько запланировано и почему есть разрыв.
- **G2.** Аналитик выгружает очищенные данные план/факт по мероприятиям за 2019–2026 одним файлом.
- **G3.** Долговой модуль отвечает на вопросы: «сколько», «кому», «в какой валюте», «под какой процент», «когда погашать», «что будет при девальвации на 10%».
- **KPI проекта:** покрытие итогов ≥ 99,5% (сумма по программам сходится с общим итогом); свежесть данных ≤ 10 дней после публикации Минфином; Lighthouse Performance ≥ 90, Accessibility ≥ 95; LCP < 2,5 с на 4G.

## 3. Функциональные модули (страницы)

Маршрутизация: `/{locale}/...`, где `locale ∈ {hy, ru, en}`. Всё состояние (год, стадия, фильтры, выбранный узел) хранится в query-параметрах, поэтому любую ссылку можно отправить и она откроет то же представление.

### 3.1. Главная — «Бюджет за 60 секунд» (`/`)
- **KPI-плитки** (выбранный год, по умолчанию текущий): доходы, расходы, дефицит (AMD и % ВВП), госдолг (AMD, USD, % ВВП), процентные расходы / доходы, исполнение расходов YTD (%). Каждая плитка: значение, Δ г/г, мини-спарклайн, бейдж источника и уровня достоверности.
- **Sankey «Откуда деньги → куда идут»**: виды доходов (НДС, налог на прибыль, подоходный налог, акцизы, таможня, гранты, прочие, заимствования) → функциональные разделы расходов (10 разделов по COFOG) + погашение долга.
- **«Из каждых 100 драмов»**: stacked bar, распределение расходов на 100 AMD.
- **Лента фактов**: 5 автоматически сгенерированных инсайтов (например, «Капитальные расходы исполнены на 89,6%») — шаблоны из данных, без LLM в рантайме.
- **Переключатель года и стадии**: Draft / Law / Revised / Actual.

### 3.2. Расходы — обозреватель (`/spending`)
- **Иерархии** (переключатель):
  1. Функциональная: раздел → группа → класс (COFOG, 10 разделов).
  2. Ведомственная: ведомство → программа → мероприятие (`ծրագիր → միջոցառում`).
  3. Экономическая: 4xxx (текущие) / 5xxx (капитальные) → статья → подстатья. Точные коды берутся из бюджетной классификации РА [VERIFY: классификатор Минфина].
- **Визуализации**: treemap с drill-down (основная), sunburst (альтернатива), таблица с сортировкой и поиском.
- **Режимы величин**: номинал AMD; реальные цены базового года (дефлятор ВВП или ИПЦ — выбор пользователя); % от общих расходов; % ВВП; на душу населения (население — Armstat); USD по среднегодовому курсу ЦБ.
- **Карточка узла** (программа/мероприятие): описание, цель, ответственное ведомство, результативные показатели (если есть в законе), ряд 2019–2026 план/факт, доля в общем бюджете, ссылки на первоисточники с номером страницы.
- **Поиск**: полнотекстовый по названиям программ на трёх языках (Fuse.js или MiniSearch по заранее собранному индексу).

### 3.3. Исполнение: план и факт, недо- и перефинансирование (`/execution`) — ядро продукта
**Определения (фиксируются в методологии и в коде):**

| Термин | Формула | Примечание |
|---|---|---|
| Initial plan (`law`) | сумма в законе о бюджете, как он принят | база «обещания» |
| Revised plan (`revised`) | годовой план с учётом всех изменений и перераспределений (`ճշտված պլան`) | Минфин обычно считает исполнение от него |
| Period plan (`period_plan`) | план на отчётный период (квартал / полугодие / 9 месяцев) | для внутригодовых отчётов |
| Actual (`actual`) | кассовое исполнение | |
| Execution rate | `actual / plan_base × 100%` | `plan_base` выбирает пользователь |
| Gap | `actual − plan_base` (AMD) | отрицательный = недофинансирование |
| Revision drift | `revised − law` | насколько бюджет переписали в течение года |

**Статусы (цвет + текст, не только цвет — доступность):**
- `Red` — исполнение < 80% (сильное недофинансирование)
- `Yellow` — 80–95%
- `Green` — 95–105%
- `Blue` — > 105% (перефинансирование)
Пороги настраиваются в `config/thresholds.yaml`.

**Визуализации:**
- **Waterfall**: закон → изменения → уточнённый план → неисполнено → факт (по году или по ведомству).
- **Heatmap**: ведомство × квартал, цвет = execution rate.
- **Scatter «размер vs исполнение»**: X = план (лог-шкала), Y = % исполнения, размер пузыря = gap. Сразу видно крупные недоисполненные программы.
- **Рейтинги**: топ-20 по абсолютному недоисполнению, по относительному, по перефинансированию; отдельный фильтр «только капитальные расходы».
- **Причины**: текстовые объяснения отклонений из пояснительных частей отчётов об исполнении (извлекаются парсером, хранятся с цитатой и номером страницы). Если причины нет — `[причина не раскрыта в отчёте]`.
- **Переносы капвложений**: с 2025 г. введён механизм переноса неосвоенных капитальных расходов на следующий год ([ARKA](https://arka.am/en/news/economy/armenia-s-2025-budget-introduces-mechanism-for-carrying-over-unrealized-capital-expenditures-to-next/)). Отдельный слой: `carryover_in`, `carryover_out`.
- **Резервный фонд Правительства**: откуда и куда перераспределено (если данные доступны в постановлениях) [UNKNOWN: полнота публикации].

### 3.4. Доходы (`/revenue`)
- Структура: налоговые доходы (НДС, налог на прибыль, подоходный налог, акцизы, экологический, таможенные пошлины, госпошлины), официальные гранты, прочие доходы.
- План/факт по видам доходов, налоги / ВВП, эластичность налогов к ВВП (расчётный показатель, помечается `calc`).
- Помесячная динамика (из ежемесячных отчётов) с сезонностью.

### 3.5. Дефицит и финансирование (`/deficit`)
- Дефицит = доходы − расходы; источники финансирования: внутренние (ОФЗ, изменение остатков) и внешние (кредиты, еврооблигации).
- Пример проверяемых данных: дефицит 2026 г. — 537 млрд AMD, из них 210 млрд внутренние и 327 млрд внешние источники ([yerkramas.org, 20.01.2026](https://www.yerkramas.org/article/199456/gosdolg-armenii-po-sostoyaniyu-na-konec-2025-goda-sostavlyaet-14-5-mlrd-dollarov)) [нужно сверить с законом].
- Первичный баланс = баланс + процентные расходы.

### 3.6. Госдолг (`/debt`) — второй ключевой модуль
**Уровни:** государственный долг (Правительство) + долг общин = госдолг; отдельно внешний долг ЦБ. Портал всегда показывает, какой агрегат выбран, потому что в СМИ эти понятия путают.

**Разрезы:**
1. Остаток: AMD, USD, % ВВП; ряд по месяцам/кварталам.
2. Резидентность: внешний / внутренний.
3. Валюта: USD, EUR, SDR (XDR), AMD, прочие (JPY, CNY и т.д. — по фактическим данным).
4. Кредитор: МВФ, ВБ (IBRD/IDA), АБР, ЕБРР, ЕИБ, ЕС, двусторонние (Россия, Германия/KfW, Франция/AFD, Япония/JICA и т.д.), еврооблигации, внутренние ОФЗ.
5. Инструмент: кредиты, еврооблигации, казначейские облигации (краткосрочные / среднесрочные / долгосрочные / сберегательные).
6. Тип ставки: фиксированная / плавающая.
7. **Средневзвешенная процентная ставка** по портфелю и по компонентам: `r_w = Σ(outstanding_i × rate_i) / Σ outstanding_i`.
8. **Структура погашений**: график основного долга и процентов на 30 лет вперёд (источник для внешней части — ЦБ, [Service schedule of foreign debt principals](https://www.cba.am/en/statistics/service-schedule-of-foreign-debt-principals/44)); ATM (average time to maturity); доля погашаемого в течение 12 месяцев.
9. **Процентные расходы**: AMD, % доходов, % расходов, % ВВП.
10. **Еврооблигации**: реестр выпусков (ISIN, купон, дата погашения, объём, текущая доходность — если доступна), например выпуск марта 2025 г.: 750 млн USD, купон 6,75%, доходность 7,1%, 10 лет ([ArmBanks, 02.05.2025](https://armbanks.am/en/2025/05/02/263512/)).
11. **Кривая доходности ОФЗ** — из [ЦБ РА](https://www.cba.am/en/yield-curves-of-gb/).

**Аналитические инструменты:**
- **Валютный стресс-тест** (слайдер ±30% USD/AMD): `Δdebt_AMD = Σ_{c≠AMD} debt_c × Δfx_c`; пересчёт долг/ВВП.
- **Декомпозиция изменения долга**: первичный дефицит + процентные платежи + курсовая переоценка + прочее (stock-flow adjustment).
  Пример для объяснения на сайте: за 1П 2026 г. долг в AMD снизился на 3,5% при почти неизменном долге в USD (5 300 → 5 116 млрд AMD; 13,91 → 13,90 млрд USD). Расчётный курс: 381,0 → 368,1 AMD/USD, то есть укрепление драма на ~3,4% [расчёт] объясняет практически всё снижение.
- **Модель динамики долга (DSA-lite)**:
  `d_t = d_{t-1} × (1 + i_t) / ((1 + g_t)(1 + π_t)) − pb_t + sfa_t`,
  где `d` — долг/ВВП, `i` — эффективная ставка, `g` — реальный рост, `π` — дефлятор, `pb` — первичный баланс/ВВП, `sfa` — stock-flow adjustment. Слайдеры: рост, инфляция, ставка, первичный баланс, курс. Горизонт — 10 лет. Показать траекторию против целевого уровня 45% ВВП ([ArmBanks, 26.06.2026](https://armbanks.am/en/2026/06/26/275449/)) и порогов бюджетного правила.
- **Бюджетные правила**: пороги долг/ВВП и последствия их превышения по Закону «О бюджетной системе» [VERIFY: текст статьи — брать из arlis.am, не из СМИ].

### 3.7. Регионы и общины (`/regions`)
- Карта 10 марзов + Ереван (GeoJSON geoBoundaries ADM1, лицензия CC BY 4.0).
- Слои: субвенции и дотации общинам, капитальные программы с региональной привязкой, расходы на душу населения (население — Armstat), показатели Armstat (безработица, бедность, ВРП при наличии) [UNKNOWN: доступность ВРП по марзам].

### 3.8. Сравнение (`/compare`)
- Год к году, проект ↔ закон, закон ↔ факт. Diff-таблица: новые программы, закрытые, наибольший рост/падение (AMD и %), реальные изменения.
- Пример для проверки: оборона в 2026 г. — 560 млрд AMD против 660 млрд в 2025 г., −15,2% [расчёт по данным [CivilNet](https://www.civilnet.am/en/news/976151/armenia-to-cut-defence-spending-by-15-in-2026/)].

### 3.9. «Мой налоговый чек» (`/my-taxes`)
Пользователь вводит месячную зарплату → расчёт подоходного налога (ставку брать из Налогового кодекса на выбранный год [VERIFY]) → распределение по функциональной структуре расходов. Дисклеймер: иллюстрация, налоги не имеют целевого назначения.

### 3.10. Data hub и методология (`/data`, `/methodology`)
- Каталог наборов данных: описание, период, единицы, лицензия, дата обновления, ссылки на CSV/XLSX/Parquet.
- Статический JSON API: `/api/v1/{dataset}/{year}.json` (генерируется при сборке).
- Методология: определения, классификации, crosswalk, формулы, правила сверки, известные ограничения.
- **Журнал сверки**: таблица расхождений между источниками (раздел 7).
- **Changelog данных**: что обновилось и когда.

## 4. Источники данных

**Правило:** первичный источник всегда выше вторичного. Иерархия: закон / официальный отчёт Минфина → Armstat → ЦБ → МВФ/ВБ → СМИ (только для сверки и как временный seed).

### 4.1. Министерство финансов РА (minfin.am) — основной источник
Армянская версия (`/hy/`) обычно полнее английской. Краулер обходит обе.

| Набор | Страница (найдена при подготовке ТЗ) | Что брать | Периодичность |

### 5.4. Краулер minfin.am: технические требования
- Обход страниц из `config/sources.yaml`, извлечение всех ссылок на `.xls/.xlsx/.pdf/.doc/.docx/.zip`.
- **TLS**: сначала стандартный контекст; при `SSLV3_ALERT_HANDSHAKE_FAILURE` — повтор с `ssl.create_default_context()` + `ctx.set_ciphers('DEFAULT@SECLEVEL=1')` и, при необходимости, `ctx.minimum_version = TLSVersion.TLSv1_2`. **Никогда** не отключать проверку сертификата (`verify=False` запрещён).
- Вежливость: 1 запрос в 2 с, User-Agent с контактом проекта, кэш по ETag/Last-Modified, соблюдение robots.txt.
- Каждый файл: `sha256`, `source_url`, `page_url`, `link_text`, `downloaded_at`, `content_type`, `bytes` → `data/raw/manifest.jsonl`.
- Классификатор документа по имени/ссылке/первой странице: `budget_law_annex`, `execution_report_q`, `execution_report_annual`, `monthly_summary`, `debt_bulletin`, `explanatory_note`, `other`.
- Fallback: если сайт недоступен, CLI `armbudget ingest-manual data/manual_drop/` принимает файлы, положенные пользователем вручную, с тем же манифестом.

## 7. Качество данных и сверка

### 7.1. Внутренние тождества (обязательные, CI падает при нарушении)
1. Σ программ = общий итог расходов (допуск 0,1%).
2. Функциональный итог = экономический итог = ведомственный итог (0,1%).
3. Доходы − расходы = дефицит; дефицит = Σ источников финансирования (0,5%).
4. Долг правительства + долг общин = госдолг (0,1%).
5. Внешний + внутренний = всего (0,1%).
6. Факт ≥ 0; стадии монотонны по датам (факт за 9 месяцев ≥ факт за полугодие для кумулятивных рядов).

### 7.2. Перекрёстная сверка источников (warn при ≥ 5%, fail при ≥ 10% — соответствует правилу «расхождения ≥ 5% разбирать»)
| Метрика | Источник A | Источник B |
|---|---|---|
| Годовые доходы/расходы/дефицит | отчёт об исполнении Минфина | ежемесячная сводка Минфина (декабрь) и Armstat |
| Госдолг | бюллетень Минфина | данные ЦБ (внешняя часть), МВФ |
| ВВП | Armstat | подразумеваемый ВВП из «% ВВП» в пресс-релизах Минфина |
| Курсы | ЦБ | подразумеваемые курсы (долг AMD / долг USD) |

**Уже найденные расхождения — должны появиться в журнале сверки с первого дня:**
| Метрика | A | B | Δ | Вероятная причина [гипотеза] |

### 7.3. Уровни достоверности (отображаются на сайте бейджем у каждой цифры)
| Метка | Значение | Бейдж |
|---|---|---|
| `verified` | взято из официального документа, страница и таблица указаны | «Официально» |
| `calc` | рассчитано порталом из `verified`-данных, формула доступна по клику | «Расчёт» |
| `assumption` | допущение (например, распределение по регионам) | «Допущение» |
| `estimate` | оценка/прогноз (DSA-lite, стресс-тест) | «Оценка» |
| `media` | временно из СМИ до появления первоисточника | «Предварительно» — жёлтый |

Правило: на главной странице не выводится ни одна цифра уровня `media`, если для неё есть `verified`.

## 8. Дизайн и UX

- **Принципы**: «сначала ответ, потом детали»; одна главная мысль на экран; каждое число — с единицей, периодом и источником.
- **Типографика**: шрифт с полной поддержкой армянского письма — `Noto Sans Armenian` + `Noto Sans` (кириллица, латиница); цифры табличные (`font-variant-numeric: tabular-nums`).
- **Форматирование чисел**: `1 234,5 млрд ֏` (ru), `1,234.5 bn AMD` (en), `1 234,5 մլրդ դրամ` (hy); всегда указан период («2026, закон», «Январь–июнь 2026, факт»).
- **Цвета**: нейтральная палитра, отдельная шкала для статусов исполнения (Red/Yellow/Green/Blue) с доступным контрастом; светлая и тёмная темы. Не использовать государственную символику и герб — сайт не должен выглядеть как официальный ресурс Правительства.
- **Доступность**: WCAG 2.1 AA, у каждого графика есть табличная альтернатива («Показать таблицу»), навигация с клавиатуры, aria-описания.
- **Мобильная версия**: графики перестраиваются (treemap → список с барами на ширине < 640px), таблицы с горизонтальной прокруткой внутри контейнера, а не страницы.
- **Производительность**: JSON-чанки на год и представление (≤ 300 КБ gzip каждый), ленивая загрузка ECharts по маршрутам, DuckDB-WASM только по требованию.
- **Дисклеймер в футере** (3 языка): «Независимый аналитический проект. Первичные данные — Министерство финансов РА, Статкомитет РА, ЦБ РА. При расхождении приоритет у официального документа.»

## 12. Операционный цикл обновления

| Событие | Триггер | Действие |
|---|---|---|
| Новый месячный отчёт Минфина | ежедневный cron находит новый sha256 | parse → validate → build → deploy; запись в changelog |
| Квартальный / годовой отчёт об исполнении | то же | + обновление `fact_narrative` и рейтингов недоисполнения |
| Новый закон о бюджете / изменения | то же | + новые программы → crosswalk review queue (issue в GitHub) |
| Долговой бюллетень | ежемесячно | обновление модуля долга, сверка с ЦБ |
| Валидация не прошла | CI fail | сайт не пересобирается, открывается issue с отчётом |
